# Closed-guard limits and catalog availability

17 October 2026. Completed offline analysis of the current v2 guard. **Live inference unchanged; paper remains exploratory.** [Protocol and reproduction](../evaluation/closed-guard-stress-protocol.md), [finite audit](closed-guard-stress-001/report.json), [captured-state catalog contrast](catalog-contrast-001/report.json).

The new independent relational interpreter evaluates67,696 synthetic guard/program/world combinations and33 handwritten grammar contract cases. These are generated software checks, not67,696 independent questions, a benchmark score, human review or a live false-rejection estimate. All canonical implementation invariants and33/33 grammar expectations pass. The audit deliberately retains counterexamples to broader semantic claims.

| Controlled question | Result | Meaning and limit |
|---|---|---|
| Do declared parent/child bindings respect the finite direct/inverse definitions? | All canonical choices pass; no nonempty canonical mismatch across4,096 parent matrices | A property of the declared finite model, not of arbitrary natural language or graph/world truth |
| Does a one-hop whitelist preserve equivalent programs? | Each correct-role identity extension is rejected despite an exact nonempty set in3,584 worlds | Controlled false rejection outside the closed family; identity is a toy relation and need not occur in the active catalog |
| Does correct direction ensure complete kinship answer scope? | Each correct-role endpoint-filtered family passes but omits valid answers in1,536 worlds | The guard enforces a necessary role condition, not all-and-only answer completeness; these extra toy filters are not current catalog outcomes |
| Does city membership prove downtown scope? | Each canonical containment form passes but exceeds the synthetic downtown set in91/216 worlds | Finer scope is not checked by this guard; the complete live pipeline and real geography are not evaluated here |
| Does city membership alone prevent arbitrary extra filtering? | The city membership plus endpoint-filter family passes but omits answers in40/216 worlds | A necessary join does not prove completeness |
| Are unsupported grammar shapes silently given a closed rule? | Declared unknowns remain unhandled in the33-case contract suite | The fallback same-model audit can still accept errors; unhandled does not mean safe abstention |

Counts overlap and are not summed into semantic accuracy. Reverse-role programs can accidentally return the expected set in some symmetric finite worlds; those rejected coincidences are distinct from the deliberately equivalent identity extensions. Empty candidate sets are retained separately; they would face the real pipeline's nonempty-result check. No model/type/semantic gate is simulated and no synthetic guard passage is described as an observed end-to-end wrong answer.

## What changed the live candidate space?

All six frozen run002 captures are retained. The gold-free audit rebuilds the schema-only catalog from the same observed state; it executes no new query or model request.

|---|---|---|---|

| Whitney original |16 /16 |Not handled / not handled |None |

This supports a narrow availability diagnosis. It does not establish that a new candidate is correct, that an old-catalog model would choose differently, or that the expanded catalog caused an accuracy gain. The latest guard-off shares the expanded catalog, so its numerical contrast cannot isolate expansion from the historical catalog. The [next design](../evaluation/closed-guard-stress-protocol.md#next-comparison-preparation-not-executable-freeze) therefore specifies separate catalog and guard factors with capture before catalog construction. The separate [nested factorial harness](../evaluation/factorial-development.md) is now implemented and fixture-tested; a small development plan is frozen separately. The larger study remains gated.
