# Semantic targeting and recovery diagnosis — development scope

16 October 2026. This work addresses the first two publication gates. It does not establish publication readiness, independent semantic accuracy or method novelty. Original v11 source, frozen comparisons and scores remain unchanged.

## Failure diagnosis

The v11 parser repeatedly returns the literal placeholder “all required constraints.” Its same-model gate can accept witnessed paths that miss the actual question. A privileged offline audit executes every recorded candidate for the original ten fixed runs, with protected labels read only after inference. Eight questions have catalogs; all eight catalogs were fully evaluated. Only four contain an exact-answer set, and those four were already answered exactly by fixed control. Two questions fail linking before any catalog exists. This is an answer-set oracle diagnostic, not a feasible-continuation or semantic-recovery label.

The annotated first relation exists in the observed inventories for Chicago, GEICO, Iran and Paul Revere. Chicago/Iran/Paul Revere lose it at the lexical top-32 stage; GEICO retains it in the shortlist but not the selected roots. Alternative predicates can nevertheless yield exact answer sets (Eli Whitney/Yale), so annotated-path matching alone is not the only valid program criterion. Original fixed and repair results remain .40/.30, with same-prefix .40/.40.

Nine official queries reproduce exact annotated answer sets under strict lexical scoring. Annie returns the typed date `1976-08-10-08:00`, while the annotation is `1976-08-10`. A result exists; this is a concrete serialization discrepancy, not evidence of missing data. The strict scorer is unchanged. A gold-free RDF literal serialization policy must be specified before final evaluation; neither a ten-case diagnostic nor a matching prefix establishes graph snapshot identity.

## New development controller

`semantic_runtime.py` wraps preserved v11 code and pins its parent hash. Its requirements quote specific question spans rather than instruction boilerplate. It applies closed answer-category/schema families, rejects reflexive named-anchor answers as an explicit scope restriction, retrieves observed answer names/types for up to five answers and requires a separate verdict with referenced program steps for every requirement. Unknown/missing verdicts abstain. This remains a same-model, uncalibrated semantic audit; type compatibility does not establish relation meaning or complete answer scope.

Revision v12 uses free string quotes and legacy retrieval. It regresses badly on the six original selected cases: zero exact, one wrong answered case, five abstentions. Quote capitalization and mixed-case entity lookup are major failures. Its GEICO path produces the correctly typed but wrong industries Auto Repair/Collision Repair; the gate wrongly treats type evidence as evidence of the requested relation. These outcomes are preserved, not suppressed.

Revision v13 constrains quotes to contiguous one-to-three-word question spans and tries a canonical-key/name/type lookup with case-insensitive name equality. The key and type checks remain mandatory; it never takes a first candidate. Contract retrieval uses the question and requirement descriptions, with the same word normalization on query and relation sides, before selecting a bounded top32 list. The full observed inventory is retained in the trace. `--root-retrieval legacy` permits a future ablation with the new semantic checks unchanged. No entity/question IDs or gold paths are injected into ranking; the type-family vocabulary is an explicit hand-written scope prior. V13 recovers three exact answers on the six original cases, abstains on Chicago and Yale, and still returns wrong GEICO industries. Yale is incorrectly assigned the inferred type musical.

Revision v14 adds two bounded schema-metadata requests to prioritize up to eight observed one-hop type-compatible relations, then fills the remaining top32 positions with lexical candidates. It supplies observed expected types to root selection. A failed inferred-type lookup can fall back to the canonical key plus observed English-name match; inferred types are hints, not authoritative facts. Fallback is logged and can still link a wrong sense. These changes may displace mediated paths or introduce new errors; they are not calibrated improvements. A four-case targeted follow-up returns two exact, one wrong and one abstention; it does not recover GEICO or Yale. V15 allows a bounded untyped name/alias fallback where canonical keys are absent; Yale remains unresolved. V16 guarantees up to two observed direct type-compatible roots within the three-root budget so root selection cannot omit every such candidate; semantic correctness still is not guaranteed. The two-case v16 check answers Mexico and GEICO exactly, recovering the diagnosed GEICO root omission while preserving the currency control. Yale remains unresolved. These are targeted engineering follow-ups, not new independent benchmark samples.

The live development set was chosen to inspect known errors and preserve working cases: Maggie Grace, Leonardo da Vinci, Mexico, Chicago, GEICO and Yale, plus four hand-authored rephrasings. The six original cases use official annotations only offline; rephrasings have no independent labels and are not assigned benchmark scores. These are purposeful regression cases, not a representative or held-out improvement sample. Multiple changes and independent model parsing prevent causal attribution without an ablation. Runtime source/config and raw outcomes are archived per revision.

## Remaining gates

- Validate regression and negative cases without relaxing checks to manufacture coverage; assess relation meaning separately from type.
- Use explicit acquisition or root expansion when a viable program is absent; choosing again from an inadequate catalog is not sufficient recovery.
- Complete named-baseline adaptation and sanity checks using [the execution specification](baseline-reproduction-plan.md).
- Collect independent semantic and continuation judgments. A generator and 30 policy-masked blank forms exist; zero independent reviewers have completed them. Do not turn their default unknown fields into measured error rates.
- Use [reserved cohort v2](reserved-training-100-v2/manifest.json), 100 unexecuted questions from train_remaining. Two near-development text matches were excluded before inference; the original flagged reservation remains as history. Exact grouping and .85 sequence-similarity screening do not prove absence of semantic paraphrases or pretraining contamination.
- An experimental, opt-in `answer_serialization` adapter now preserves raw RDF terms while projecting common-era xsd:date values to their written calendar date. It is not wired into the archived controllers or scores and does not assert timezone equivalence. Validate and freeze representation policy before evaluation.
- Freeze method, normalization, baselines, metrics, seeds and resource budgets before using the reserved cohort. Official test remains unexecuted. No extra infrastructure/model purchase is needed for immediate work.
